# Fulda Gap 任务闭环（生效）

参数已由用户确认。配置位于 `Scripts/Data/Scenarios/Fulda_Gap/missions.json`，任务状态与计算在 `Scripts/Systems/Victory/MissionTracker.cs`。不新增固定回合自动结束，仍为手动结束或一方全灭结束。

## 区域与操作

两个关键节点为巴德赫斯费尔德 `(13,8)` 与富尔达 `(13,28)`；华约出口为西侧道路边界 `(0,8)`；北约撤离区为 `(0,8)` 与南侧后方道路 `(14,29)`。这些是基于当前粗化地图的任务设计位置，不声称是查实的战时行动计划。

地图显示节点与出口标记，“任务与区域”按钮展示位置、条件、分数、首次突破回合和退出名单。到达出口后选中本方单位，在战略阶段点击“突破／撤离所选单位”；移动动画、战斗、终局后不能执行。退出不自动发生，不额外消耗 AP，代表通过地图边界。

## 有效突破与撤离

- 单位必须存活、未达到全营歼灭门槛，CE≥50%，疲劳≤8；所在出口由本方控制，实时补给 SP>0。
- 华约还须是主战营；出口沿本方控制且通行的道路 / 高速道路格，与东侧指定补给入口连通。只占出口不够，侦察支援棋子不计突破。连接遵守河流关闭边。
- 北约任何合格单位可以撤离，但只有第1、第3骑兵中队计入保存效能任务分。炮兵撤离不会额外增加保存分。
- CE 使用现行模型的存活子单位 Cost 比例，不是当前 HP 比例或真实人员比例。
- 成功退出时保存该单位完整状态、CE与回合，移出在场列表；不再投射 ZOC、移动、参战、接受补给结算或恢复效能。不会凭退出直接把周边格重新分配给敌方，格子随后按正常控制规则变化。
- 同一个单位 ID 只能退出一次，不能返回地图。退出单位不是阵亡单位，不能给对方增加战损分。全灭判断包括已退出的存活单位，因此撤走最后一个在场单位不等于全灭；可继续行动或手动结束。

## 任务分

华约突破分 = `70 × min(累计突破CE / 2, 1)`；两个关键节点在结算时由华约控制，各得15分。节点分按当前控制计算，不反复累计；撤离后即使节点失守也不抹除已获得的突破分。

北约迟滞分 = `70 × 已计迟滞完整回合 / 12`。双方各完成一次行动才计一个完整回合；最多计12回合（24小时），首次有效突破所在回合及其后不再获得迟滞分。只完成北约半回合不计分。窗口达到后冻结收益，不自动结束游戏，后续突破、撤离和节点控制仍影响结算。

北约保存分 = `30 × (第1中队撤离CE + 第3中队撤离CE) / 2`。未撤离的部队不获得保存分；退出时效能冻结，不随后增长。两方各最多100分，提前手动结束只结算已经获得的分数，不补发尚未经过的迟滞时间。

任务分替代普通格占领累计分与战损 VP 决定胜负。保持既有七档分比评定阈值，以北约任务分 / 华约任务分计算，双方0分按1处理，一方0分按0.1或10封顶。内部使用浮点计算，在任务界面显示一位小数，不先将每回合70/12分取整。战损统计仍显示；现有内部战损Cost统计保留，但不加入任务胜负。

## 存读档与验证

完整对局存档升为版本2，包含任务配置ID、完整回合数、迟滞回合数、首次突破回合及退出单位档案。版本1缺少任务历史，拒绝加载，不通过推断补发分数。

加载先验证任务回合关系、首次突破记录、CE、单位ID唯一性与在场 / 退出列表互斥，再修改对局；拒绝重复退出、效能不一致和不合法任务记录。重新开局清除全部任务进度。

`MissionTests` 已接入总运行器，覆盖门槛拒绝、道路连通、首次突破、重复计分、收益窗口、节点分、战损不影响任务结果，以及真实会话的撤离、文件存读档、全灭判断和重新开局。
