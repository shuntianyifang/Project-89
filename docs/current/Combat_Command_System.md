# 战斗命令系统：首版改造边界

## 已确认的方向

本项目仍是兵棋。玩家按编组下达命令，命令决定什么兵力在什么条件下进入火力、能力与伤亡计算；命令本身不直接提供攻防倍率。保留现有装备和抽象裁定工具，不加入逐车操作、逐发弹道或实时操作要求。

新系统实际结果更新对局；旧系统在战前深拷贝上独立计算，只显示对照。旧对照保留四插槽输入与现行代码行为，不要求新旧结果一致。对照必须列出参战名单、假设与随机种子；其差异不能直接称为命令收益。

## 必须先固定的约定

| 项目 | 首版约定 / 状态 |
| --- | --- |
| 身份与编制 | 连下令，子单位提供火力与损失；引用原营和连，不复制或重置兵力 |
| 双方公平性 | 双方锁定计划后自动裁定；被攻击单位不能靠“不投入”免于接触 |
| 三种集合 | 到场兵力、提供作用的兵力、暴露于某类威胁的兵力必须区分 |
| 状态更新 | 本阶段结束后更新，再在下一阶段检查触发条件；不读取未来结果 |
| 对照 | 战前快照、旧规则、独立随机数、只读结果，不计VP、不扣实际AP |
| 生效范围 | 实验规则单独说明；未确认参数之前不替换实际对局 |
| 规则冲突 | 断补乘数与旧文档扣分、统一交战地形与按营地形的冲突待确认 |

## 已确认的首版实验参数

按连选择前沿、预备、支援、不投入；3个等时阶段，预备在前沿已投入兵力CE低于80%时于下一阶段接替。实际投入的营每场扣既有4 AP一次，疲劳按所参与阶段CRT最高档结算一次。阶段损失率为 `1-(1-旧CRT损失率)^(1/3)`，不能重复应用整场CRT。

首版先验证无断补、平原条件，地形与断补口径仍待决，不将当前代码口径自动升级成新规则。阶段是一次战斗的内部归一化片段，不是新的战役回合。

接替条件按原前沿连的存活子单位Cost比例计算，不以临时分组重新定义总兵力。触发后原前沿转入后方，预备成为前沿；同一连不同时属于两种作用。命令按本阶段开始时的已知状态判定，损失不会反过来改变本阶段已经投入的兵力。

炮兵 / 预备暴露路由及取消全营30%清空规则已提出单独确认，未确认前不生效。不承诺首版具备尚未模拟的包抄、视线、压制或自动战役退格。

## 可通过测试调整的内容

阶段数与对应的损失尺度、接替门槛、阶段投入顺序、支援暴露权重、命令默认方案、UI文案、反馈排序均可配置或迭代，但行为变更仍需同步规则和回归测试。只有一份参数版本是生效基线，不在正常对局中暗中调整。

以下不能仅靠调数值解决：同一兵力重复投入、未投入部队提供标签、对照污染实际状态、阶段次数凭空放大损失、命令读取隐藏敌情或未来结果。

## 实验与反馈

当前代码已提供命令计划校验、阶段接替选择器、阶段投入报告和独立旧系统对照。投入报告按原营组织度与疲劳聚合当前投入连的存活子单位攻防，列出能力标签；等待预备、不投入、已接替前沿不提供火力。报告是阶段开始时的值快照，不裁定协同覆盖或伤亡暴露，也不是最终战果预测。全部连投入时聚合攻防应与原营相同，不额外增加棋子数量奖励。

伤亡路由、整营低于30%是否清空，以及断补和地形口径确认后，才能完成新裁定器与实际对局接入。目前正常对局仍使用原裁定器，未把结构性原型误当成完整的新战斗系统。

训练 / 测试报告对照全投入、预备接替、仅支援、保留兵力等计划，记录每阶段投入原因、未投入原因、作用与暴露名单、优势修正、损失及消耗。评价目标包括任务与后续能力，不以单场击毁比给命令排固定优劣。

回归测试至少覆盖兵力身份唯一、重复命令拒绝、预备触发时序、炮兵与前沿伤亡隔离、未投入不扣实际成本、随机种子可重复、旧对照不改实际状态、正常会话只记录一次实际战损。阶段稳定性实验需报告累计损失；归一化公式不保证标签、组织阈值与随机分摊引起的结果完全一致。

## 后续必须另定的规则

战场宽度、到场 / 展开延迟、压制状态、损失容忍与撤退路线、连级配属、兵种支援覆盖容量尚未给出生效参数。首版不能宣称这些机制已经完成。改造按“命令与对照结构 → 阶段裁定测试 → 实际对局命令面板 → 宽度及撤退”推进。
