# 游戏调试模式

F8 开关补给调试面板；F10 切换检查阵营（1 蓝 / 2 红）；F9 或面板按钮导出当前状态。开启后悬停格子可查看双方 SP、所属方、地形道路、敌军阻断者及剩余 AP、所在部队疲劳和上次 OOS。地图亮线表示检查阵营实际获胜的补给路径，面板列出来源类型、来源坐标和归属、源预算、累计成本。枢纽路径从最后一次重置 SP 的枢纽开始。

也可设置环境变量 `CW_DEBUG_MODE=1`，使游戏启动即开启调试面板。

开启调试后悬停优先显示补给路径；正常移动和结束回合仍可使用。F6 可同时查看补给覆盖，F7 查看控制权。调试信息展示双方完整数据，包括战争迷雾中的敌人。该模式不修改规则或单位状态，默认关闭；只在开启期间记录最近 8 个补给结算前后状态。

快照保存在 Godot `user://debug_snapshots/`，面板显示绝对文件路径，导出时路径复制到剪贴板，输出日志也包含 `[DEBUG SNAPSHOT]`。将 JSON 路径提供给 agent 即可检查，不必凭截图重建局面。

JSON schema_version=1：包含 UTC 时间、Godot 版本、程序集 build ID、当前规则参数、回合阶段、检查坐标、所有格子的地形/道路/可通行性/归属/设施、所有营的位置/AP/疲劳/OOS/模板和标签，以及双方各格的 SP、显示 SP、阻断标记和获胜路径。cells 中每项明确存储 x/y，避免矩阵转置歧义。路径为空表示没有补给；SP=0 的原因可能是阻断、断连或成本超过预算，需要结合导出的邻格和单位判断。

诊断 SP 和路径来自实际 SupplyManager / SupplyNetwork；同时保留最近一次显示 SP，结算前后导出可能显示旧的显示值，便于检查更新时间差。快照是补给复现场景，不是完整游戏存档，不能恢复战斗实体的 HP 和编制。

## 自动复算

先 `dotnet build "Project 89.csproj"`，再运行：

```powershell
$env:CW_SUPPLY_REPLAY = 'C:\完整路径\supply-快照.json'
& 'D:\Godot_v4.7.2-stable_mono_win64\Godot_v4.7.2-stable_mono_win64_console.exe' --headless --path 'D:\project-89'
Remove-Item Env:CW_SUPPLY_REPLAY
```

复算当前快照及记录的结算快照，输出每个不一致 SP 的阵营和坐标；存在差异或读入失败时退出码为 1，无差异为 0。优先于 CW_RUN_TESTS；复算不启动游戏、不写占领状态。不同版本间出现差异应检查规则及程序集 build ID。
